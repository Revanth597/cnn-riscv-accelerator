# Firmware Design

## Overview

The firmware provides the software layer that controls the CNN hardware accelerator integrated with the PicoRV32 processor.

It is responsible for:

- Configuring the CNN accelerator using custom RISC-V instructions
- Managing CNN execution
- Reading accelerator outputs
- Performing programmable post-processing
- Writing the processed feature maps back into memory

The firmware is implemented using a combination of **RISC-V assembly** and **C**, allowing direct hardware control while maintaining flexibility for configurable post-processing.

---

# Firmware Responsibilities

The firmware performs the following major tasks:

- Configure CNN weight parameters
- Configure image parameters
- Trigger CNN execution
- Read INT16 feature maps generated by the accelerator
- Perform Max Pooling
- Apply intermediate scaling
- Perform arithmetic right shift
- Quantize outputs to INT8
- Clamp values to the valid INT8 range
- Store the final feature map back into BRAM

The firmware acts as the software controller for the CNN accelerator while implementing the complete post-processing pipeline.

# Custom Instruction Interface

The firmware communicates with the CNN accelerator using two custom RISC-V instructions.

## CNN_LD_WT

Purpose:

- Load weight base address
- Configure input channels
- Configure output channels

This instruction initializes the weight-related configuration registers inside the accelerator.

---

## CNN_LD_IMG_EXE

Purpose:

- Load image base address
- Configure destination buffer
- Configure image size
- Assert `start_cnn`

This instruction completes accelerator configuration and initiates CNN execution.

The firmware exchanges data with the accelerator through BRAM.

# Accelerator Output

The RTL accelerator performs:

- Weight Loading
- Image Loading
- Convolution
- MAC Computation
- ReLU Activation

The generated feature map is written to BRAM as **INT16** data.

This INT16 feature map becomes the input to the firmware post-processing pipeline.

---

# Firmware Post-Processing

The complete post-processing pipeline is implemented in software.

```
Read INT16 Feature Map
        │
        ▼
Max Pooling (2×2)
        │
        ▼
INT16
        │
        ▼
Read Intermediate Scale
        │
        ▼
INT16 × UINT16 (Q16)
        │
        ▼
INT32
        │
        ▼
Arithmetic Right Shift
        │
        ▼
Quantization
        │
        ▼
Clamp to INT8
        │
        ▼
Store INT8 Output
```

The firmware converts the accelerator output into the quantized feature map required for subsequent CNN processing.

---

# Max Pooling

Max Pooling is the first post-processing operation performed by the firmware.

Implementation:

- Window Size : 2 × 2
- Stride : 2
- Channel-wise operation

For every pooling window, the maximum value among the four neighbouring pixels is selected.

The pooled output remains in **INT16** format.

---

# Intermediate Scaling

Each output channel uses an independent intermediate scaling factor stored in firmware.

The scaling factors are represented as **16-bit fixed-point (Q16)** values.

The pooled INT16 value is multiplied by its corresponding scaling factor.

```
INT16 × UINT16(Q16)

↓

INT32
```

The scaling values compensate for quantization performed during CNN model generation.

---

# Arithmetic Right Shift

After multiplication, the INT32 result is shifted right by sixteen bits.

```
product >>= 16
```

This converts the fixed-point multiplication result back into the desired numerical range before quantization.

---

# Quantization

The shifted INT32 value is converted into INT8.

```
INT32

↓

INT8
```

Quantization significantly reduces memory usage while maintaining CNN inference accuracy.

---

# Clamping

After quantization, the firmware clamps every value into the valid INT8 range.

```
-128 ≤ Output ≤ 127
```

Values exceeding this range are saturated before storage.

---

# Output Buffer

The final quantized feature map is written back into BRAM.

Output format:

```
INT8
```

The stored feature map becomes the input for the next CNN layer or can be used for verification and debugging.

---

# Data Types

The firmware processes multiple numerical formats.

| Stage | Data Type |

# Hardware / Software Partition

The CNN inference pipeline is partitioned between hardware and firmware.

## RTL Accelerator

Responsible for:

- Weight Loading
- Image Loading
- Convolution
- Multiply-Accumulate (MAC)
- ReLU Activation
- INT16 Feature Map Generation

---

## Firmware

Responsible for:

- Max Pooling
- Intermediate Scaling
- Arithmetic Right Shift
- Quantization
- Clamping
- Output Feature Map Storage

This partition allows computationally intensive operations to execute in dedicated hardware while keeping post-processing programmable in software.

# Summary

The firmware provides the software control layer for the CNN hardware accelerator integrated with PicoRV32.

It configures the accelerator using custom RISC-V instructions, manages accelerator execution, performs programmable post-processing, and stores the final INT8 feature maps back into BRAM.

The combination of RTL hardware acceleration for convolution, MAC, and ReLU together with firmware-based Max Pooling, intermediate scaling, quantization, and output formatting provides a flexible and efficient hardware/software co-design suitable for embedded CNN inference.
